############# UI/UX DESIGN  ############

Design a complete, production-quality responsive web application called “Milestone”.

PRODUCT
Milestone is a modern escrow-backed project management marketplace connecting clients with freelancers.

A client funds a project upfront, divides the project into milestones, assigns milestones to one or more freelancers, and funds are held in simulated escrow until each milestone is approved.

Milestone lifecycle:

NOT STARTED
→ IN PROGRESS
→ SUBMITTED
→ APPROVED
→ PAID

Submitted milestones have a 72-hour countdown before automatic release.

If either party opens a dispute, the milestone is frozen and the countdown stops.

IMPORTANT:
This is an MVP with simulated wallet, simulated escrow and simulated identity verification. Do not design real banking or financial transaction interfaces.

DESIGN SYSTEM

Create a consistent design system across the entire application.

Typography:
Use a modern professional sans-serif such as Inter, Geist, or a similar contemporary UI font.

Typography hierarchy:
- Large dashboard headings
- Medium section headings
- Compact labels
- Highly readable body text
- Clear financial/statistical numbers

Spacing:
Use an 8px spacing system.

Corners:
Use restrained rounded corners, approximately 10–16px.

Cards:
Use premium cards with subtle borders, soft shadows where appropriate, and strong internal spacing.

Buttons:
Use clear primary, secondary, tertiary and destructive variants.

Inputs:
Large enough for comfortable desktop and mobile use.

Icons:
Use a consistent minimal line-icon system.

Charts:
Minimal and informative, never decorative.

Color system:
Create a sophisticated neutral foundation with one strong brand accent.

Use:
- light background
- white/near-white surfaces
- dark primary text
- muted secondary text
- subtle borders
- green for successful/released/paid states
- amber for pending/in-progress states
- red for disputes/errors
- blue or the chosen brand accent for primary actions

Do not use colors excessively.

BENTO GRID SYSTEM

Use a responsive bento-grid layout for dashboards and information-heavy screens.

Cards should have different visual weights.

Examples:
- large project overview card
- medium wallet card
- milestone progress card
- activity card
- deadline card
- AI assistant card
- recent messages card

Use asymmetrical but structured layouts.

The bento grid must remain functional rather than decorative.

DESKTOP
Design primarily for 1280px+ desktop screens.

Use:
- persistent sidebar
- spacious content area
- multi-column bento layouts
- split panels where appropriate
- sticky contextual actions when useful

TABLET
Design for approximately 768px.

Adapt:
- sidebar to compact/collapsible navigation
- bento grids to fewer columns
- tables into responsive cards
- split views into stacked layouts where necessary

MOBILE WEB
Design for approximately 390px.

Use:
- single-column layouts
- bottom navigation or compact navigation where appropriate
- stacked cards
- full-width primary actions
- horizontally scrollable tabs only when necessary
- simplified tables
- full-screen chat
- optimized forms

Never allow horizontal overflow.

IMPORTANT DESIGN PRINCIPLES

1. Build a cohesive design system before individual screens.
2. Reuse components aggressively.
3. Keep financial information extremely clear.
4. Make project/milestone status immediately understandable.
5. Make the approval/release workflow impossible to misunderstand.
6. Make client and freelancer experiences feel related but distinct.
7. Use bento layouts where they improve information hierarchy.
8. Prioritize usability over decoration.
9. Make every screen feel production-ready.
10. Maintain consistent spacing, typography, iconography and interaction patterns across the entire product.

FINAL OUTPUT

Generate the complete Milestone web design system and all major web application screens described above.

Create a cohesive, production-ready responsive design system that can later be implemented in Next.js + React + Tailwind CSS.

The design should be detailed enough that an AI coding agent can use the Stitch screens as the source of truth for implementation.

Do not generate random screens that are not part of the product.

Do not invent business features outside the scope described above.
